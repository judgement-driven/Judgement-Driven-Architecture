# JDA v1.7 に向けて考えるべき論点

## 1. v1.6で整理されたもの

v1.6では、JDAの基本構造整理が大きく進んだ。

特に重要なのは以下。

```text
BJ = 発見スコープ
JP = 判断点
JJ = 実行によって形成される連鎖
```

これにより、

- 発見（Phase0/1）
- 設計（Phase3）
- 実行（Phase5）
- 学習（Phase6）

の責務分離が明確になった。

また、

```text
「JPを作る」
=
判断材料提示・状態遷移・JLog/VLog収集を実装すること
```

へ整理されたことで、

「AIが判断するシステム」ではなく、

```text
人間判断を実行可能・学習可能にする構造
```

へ軸足が移った。

---

# 2. v1.7で重要になる論点

## 2.1 判断と状態遷移の境界

現在のJDAは、状態遷移モデルにかなり近い。

```text
状態観測
↓
判断
↓
状態遷移
```

ただし、以下がまだ混在している。

```text
判断 = 状態遷移条件
判断 = 行為選択
判断 = 状態そのもの
```

これは execute_jp の定義に直結する。

特に、

```text
JDAはワークフローエンジンなのか？
```

という誤解を避けるためにも整理が必要。

---

## 2.2 JP粒度問題

現在のJP粒度は、実務感覚ベースで定義されている。

例：

```text
「接触するか？」
```

はJPとして扱っているが、

```text
「電話するか？」
「メールするか？」
```

まで分けるのかは未定義。

将来的には、

```text
状態変化を伴う最小責任判断
```

のような基準が必要になる可能性がある。

---

## 2.3 Condition / Perspective / Hypothesis の分離

これはv1.7で最も重要な論点候補。

現在のJDCでは主に、

```text
Condition
Perspective
```

を扱っている。

しかし実際の人間判断は、

```text
仮説
↓
観測
↓
補強
↓
判断
```

で動いていることが多い。

例えば営業判断では、

```text
「この企業は広告を打ちたいのでは？」
```

という仮説を持ち、

- 返信速度
- 会話内容
- 温度感
- 予算感

を観測している。

つまり実際の構造は、

```text
Hypothesis
↓
Perspective
↓
Condition
↓
Decision
```

に近い。

---

# 3. JDC進化の可能性

将来的なJDCは、

```text
Condition
= 判定条件

Perspective
= 解釈フレーム

Hypothesis
= 現在持っている仮説
```

の三層構造になる可能性がある。

これは営業AI補強画面にも既に現れ始めている。

例えば：

```text
媒体適合スコア
ブランドスコア
長期効果
ニッチターゲット
```

などは単なるスコアではなく、

```text
「この企業はこの企画に合う」
```

という仮説の補強材料として機能している。

つまりAIは、

```text
判断
```

ではなく、

```text
仮説提示
観測補強
```

を行っている。

---

# 4. JLog / VLog の進化

Hypothesis が導入されると、
JLog / VLog の意味も変化する。

現在：

```text
入力
条件
観点
結果
```

将来：

```text
仮説
↓
観測
↓
判断
↓
結果
↓
妥当性
```

これにより、

```text
なぜ失敗したか
```

だけでなく、

```text
どの仮説がズレていたか
```

を学習できるようになる。

例：

```text
仮説：
担当者が強く推進している

結果：
決裁者が否定的だった

学習：
担当温度感だけでは不十分
```

これは単なる判断ログではなく、

```text
思考ログ
```

に近づく。

---

# 5. execute_jp の再定義可能性

現在の execute_jp は、

```python
execute_jp(case_id, proposal_id, jp_id, ...)
```

として整理されている。

しかし実態としては、

```text
JP定義読込
↓
状態更新
↓
ログ保存
```

に近く、
ワークフローエンジン的性質を持つ。

そのため今後、

```text
JDAの本質は execute_jp ではなく、
JLog/VLog学習ループではないか？
```

という再整理が発生する可能性がある。

---

# 6. v1.7の方向性（仮）

v1.6は、

```text
判断を実行可能にする
```

段階だった。

v1.7では、

```text
判断を学習可能にする
```

方向へ重心が移る可能性がある。

特に重要なのは、

```text
AIが何を判断したか
```

ではなく、

```text
人間が何を仮説として見ていたか
```

を構造化すること。

その結果、

```text
JDA = 判断実行アーキテクチャ
```

から、

```text
JDA = 判断学習アーキテクチャ
```

へ進化する可能性がある。
